# 前端宽高属性核心笔记（window/document/HTMLElement）
## 核心认知（先记底层逻辑）
所有宽高属性本质对应 3 类“测量对象”，记准对象就能避开 80% 的错误：
- ✅ Window：测量**浏览器窗口/视口**（显示网页的区域）
- ✅ Document：测量**整个HTML文档**（包含视口外的滚动内容）
- ✅ HTMLElement：测量**单个DOM元素**（如div、img、button）

---

## 一、Window 宽高属性（浏览器窗口/视口）
### 核心属性表（只记常用的，冗余的直接忽略）
| 属性                | 通俗含义                                                                 | 实用场景                     |
|---------------------|--------------------------------------------------------------------------|------------------------------|
| window.innerWidth   | 视口宽度（显示网页的区域）：不含浏览器工具栏/边框，**包含滚动条宽度**     | 响应式布局、获取当前视口宽度 |
| window.innerHeight  | 视口高度：规则同上                                                       | 判断视口高度、移动端适配     |
| window.outerWidth/Height | 整个浏览器窗口宽高（含边框/工具栏） | 几乎不用（仅桌面端调试）|

### 代码示例（可直接控制台运行）
```javascript
// 开发中最常用：获取视口尺寸
console.log('视口宽度：', window.innerWidth);
console.log('视口高度：', window.innerHeight);

// 对比（仅调试用）
console.log('浏览器窗口总宽度：', window.outerWidth);
```

### 关键提醒
- PC 端垂直滚动条会占用 `innerWidth` 空间（约 17px），移动端无此问题（悬浮滚动条）；
- 移动端 `innerWidth` 就是屏幕可视宽度，无需额外计算。

## 二、Document 宽高属性（整个HTML文档）
### 核心属性表（优先用html根节点，避开body坑）
| 属性                                  | 通俗含义                                                                 | 实用场景                     |
|---------------------------------------|--------------------------------------------------------------------------|------------------------------|
| document.documentElement.clientWidth  | 等同于 window.innerWidth（视口宽度），**兼容性更好**                     | 兼容老旧浏览器的视口宽度     |
| document.documentElement.clientHeight | 等同于 window.innerHeight（视口高度），**兼容性更好**                     | 兼容老旧浏览器的视口高度     |
| document.documentElement.scrollWidth  | 文档总宽度（包含视口外的横向内容）                                       | 判断是否有横向滚动           |
| document.documentElement.scrollHeight | 文档总高度（包含视口外的纵向内容）                                       | 判断滚动到底部、懒加载触发  |

### 代码示例（含高频业务场景）
```javascript
// 1. 兼容写法：获取视口尺寸（适配所有浏览器）
const viewportWidth = window.innerWidth || document.documentElement.clientWidth;
const viewportHeight = window.innerHeight || document.documentElement.clientHeight;

// 2. 高频场景：判断是否滚动到页面底部
window.addEventListener('scroll', () => {
  const docTotalHeight = document.documentElement.scrollHeight;
  const scrollTop = document.documentElement.scrollTop; // 已滚动的高度
  // 预留 10px 误差，避免因精度问题判断失效
  const isBottom = scrollTop + viewportHeight >= docTotalHeight - 10;
  
  if (isBottom) {
    console.log('已滚动到页面底部！'); // 可触发懒加载、加载更多等逻辑
  }
});
```

### 关键提醒
❌ 禁止使用 `document.body.scrollHeight`！  
`body` 的 margin/padding 样式会篡改其值，`document.documentElement`（html根节点）更稳定，是行业通用写法。

## 三、HTMLElement 宽高属性（单个DOM元素）
这是最易混淆的部分，按“计算范围”分类记，而非死记属性名。

### 核心属性对比表（核心中的核心）
| 属性                | 计算范围（通俗版）                          | 实用场景                     |
|---------------------|---------------------------------------------|------------------------------|
| element.clientWidth | 可视宽度 = 内容宽 + padding - 滚动条宽度    | 获取元素可显示内容的宽度     |
| element.clientHeight| 可视高度 = 内容高 + padding - 滚动条高度    | 获取元素可显示内容的高度     |
| element.offsetWidth | 占位宽度 = 内容宽 + padding + border         | 获取元素在页面的实际总宽度   |
| element.offsetHeight| 占位高度 = 内容高 + padding + border         | 获取元素在页面的实际总高度   |
| element.scrollWidth | 内容总宽度（包含滚动出可视区域的部分）      | 判断元素内容是否横向超出     |
| element.scrollHeight| 内容总高度（包含滚动出可视区域的部分）      | 判断元素滚动到底部           |

### 可视化示意图（一看就懂）
```plaintext
+----------------------- offsetWidth/Height ------------------------+
| 边框（border）                                                    |
|  +------------------- clientWidth/Height -------------------+    |
|  | 内边距（padding）                                        |    |
|  |  +--------------------- 内容区域 ---------------------+  |    |
|  |  |                                                     |  |    |
|  |  |                scrollWidth/Height                   |  |    |
|  |  |（包含滚动隐藏的内容）                               |  |    |
|  |  +-----------------------------------------------------+  |    |
|  |                                                          |    |
|  +----------------------------------------------------------+    |
|                                                                   |
+-------------------------------------------------------------------+
```

### 代码示例（实操验证，控制台可运行）
```html
<!-- 先准备测试元素 -->
<div id="test-box" style="
  width: 200px; height: 150px;
  padding: 10px; border: 5px solid #000;
  overflow: auto; /* 出现滚动条 */
">
  测试内容<br>测试内容<br>测试内容<br>测试内容<br>测试内容<br>
  测试内容<br>测试内容<br>测试内容<br>测试内容<br>测试内容<br>
</div>

<script>
const box = document.getElementById('test-box');
// 对照表格看结果，秒懂差异
console.log('clientWidth（内容+padding-滚动条）：', box.clientWidth); // 203
console.log('offsetWidth（内容+padding+border）：', box.offsetWidth); // 230
console.log('scrollHeight（内容总高度）：', box.scrollHeight); // 大于150
</script>
```

### 补充：getBoundingClientRect() 中的宽高
| 特性                | offsetWidth/Height | getBoundingClientRect().width/height |
|---------------------|--------------------|--------------------------------------|
| 数值精度            | 整数（像素取整）   | 小数（精准到小数点后）               |
| CSS 缩放适配        | 结果不精准         | 准确反映元素实际显示尺寸             |
| 实用场景            | 普通尺寸获取       | 精准测量（如缩放、动画场景）         |

---

## 核心易错点&避坑指南
1. ❌ 混用“视口”和“元素”属性：比如用 `document.body.offsetWidth` 代替视口宽度；
2. ❌ 直接赋值只读属性：`element.offsetWidth = 300` 无效，改尺寸只能用 `element.style.width = "300px"`（带单位）；
3. ❌ 用 `style.width` 获取非行内样式：CSS 类里的样式需用 `getComputedStyle(element).width` 获取；
4. ❌ 依赖 `document.body` 测文档尺寸：优先用 `document.documentElement`。

---

## 速记总结（按场景选属性）
| 需求场景                | 首选属性                                      |
|-------------------------|-----------------------------------------------|
| 获取浏览器视口尺寸      | window.innerWidth/Height（兼容加 html.client） |
| 获取文档总高度（滚动）| document.documentElement.scrollHeight          |
| 获取元素实际占位尺寸    | element.offsetWidth/Height                    |
| 获取元素可视区域尺寸    | element.clientWidth/Height                    |
| 获取元素内容总尺寸（滚动） | element.scrollWidth/Height                   |
| 精准测量元素显示尺寸    | element.getBoundingClientRect().width/height   |

---

### 总结
1. 所有宽高属性先分清“测量对象”（window/文档/元素），是避坑的核心；
2. 记“场景”而非记“属性名”：按需求场景选属性，比死记属性定义更高效；
3. 元素尺寸重点区分 3 类计算范围：可视区（client）、占位（offset）、内容总尺寸（scroll）。
