# 7. Rubbo使用

## 题外话

本文只是简单讲解如何快速使用Rubbo，其它资料的学习请前往官方网站提供的学习文档[Dubbo 文档 | Apache Dubbo](https://cn.dubbo.apache.org/zh-cn/overview/home/)



## ①介绍【RPC的一种】

简单说就是个「服务管家」，专门解决分布式系统中服务之间互相调用的麻烦事【为什么要使用分布式系统呢？互联网场景中所要面对的用户规模和体量的增加，系统也需要做相应的拆分设计和实现】。比如你的系统拆成10个微服务，A服务想调用B服务时，Dubbo能让这个过程像在同一个程序里调方法一样简单，不用自己写复杂的网络通信代码‌



## ②怎么使用？【以IDEA环境举例】

### ‌**▌ 第一步：快速搭建环境**‌

1. 打开IDEA，新建一个Spring Boot项目
   - 选择菜单 `File > New > Project > Spring Initializr`
   - 包名随意(如`com.example.dubbo-demo`)，Java版本选17
   - ‌**依赖只选`Spring Web`**‌（其他后面手动加）
2. 检查`pom.xml`，确认有基础Spring Boot依赖：

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.2.0</version> <!-- 默认是最新稳定版 -->
</parent>
```



### ‌**▌ 第二步：打入Dubbo依赖**‌

在`pom.xml`中添加这些依赖（放在`<dependencies>`标签内）：

```xml
<!-- Dubbo核心依赖 -->
<dependency>
    <groupId>org.apache.dubbo</groupId>
    <artifactId>dubbo-spring-boot-starter</artifactId>
    <version>3.2.0</version>
</dependency>

<!-- 使用Zookeeper当通讯录（注册中心） -->
<dependency>
    <groupId>org.apache.dubbo</groupId>
    <artifactId>dubbo-registry-zookeeper</artifactId>
    <version>3.2.0</version>
</dependency>

<!-- Zookeeper客户端 -->
<dependency>
    <groupId>org.apache.zookeeper</groupId>
    <artifactId>zookeeper</artifactId>
    <version>3.8.3</version>
    <exclusions>
        <exclusion>
            <groupId>org.slf4j</groupId>
            <artifactId>slf4j-log4j12</artifactId>
        </exclusion>
    </exclusions>
</dependency>
```

### ‌**▌ 第三步：配置服务通讯录**‌

在`src/main/resources/application.yml`中添加：

```yml
dubbo:
  application:
    name: dubbo-demo # 应用名随便起，但要有
  protocol:
    name: dubbo  # 使用dubbo协议
    port: 20880   # 服务暴露的端口（默认20880）
  registry:
    address: zookeeper://127.0.0.1:2181  # 注册中心地址
  scan:
    base-packages: com.example.dubbo-demo.service  # 扫描Dubbo服务的包路径
```

### ‌**▌ 第四步：先写个服务接口**‌

1. 新建包`com.example.dubbo-demo.service`
2. 在包内新建接口`UserService`：

```java
public interface UserService {
    String getUserName(Long userId);
}
```

### ‌**▌ 第五步：实现服务（生产者）**‌

在同一个包下创建实现类：

```java
import org.apache.dubbo.config.annotation.DubboService;

@DubboService // 关键！声明这是Dubbo服务（不是Spring的@Service）
public class UserServiceImpl implements UserService {
    @Override
    public String getUserName(Long userId) {
        // 模拟数据库查询
        return "用户_" + userId; 
    }
}
```

### ‌**▌ 第六步：启动服务提供者**‌

修改主启动类，加上Dubbo支持：

```java
@SpringBootApplication
@EnableDubbo // 启用Dubbo功能
public class DubboDemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DubboDemoApplication.class, args);
    }
}
```

### ‌**▌ 第七步：消费者调用（另一个模块）**‌

由于是单项目演示，我们在同一项目内模拟消费者：

1. 新建`TestController`：

```java
@RestController
public class TestController {
    
    @DubboReference // 自动注入远程服务
    UserService userService;

    @GetMapping("/test")
    public String test() {
        return userService.getUserName(100L); 
    }
}

```

### ‌**▌ 第八步：点火发射！**‌

1. ‌**先启动Zookeeper**‌（注册中心）：
   - 下载ZooKeeper：https://zookeeper.apache.org/releases.html
   - 解压后进入`bin`目录，执行：
     `./zkServer.sh start` (Mac/Linux)
     `zkServer.cmd` (Windows)
2. 在IDEA中启动Spring Boot应用
3. 浏览器访问：http://localhost:8080/test
   应该看到返回 `用户_100`

### ‌**▌ 可能遇到的坑**‌

1. ‌**Zookeeper连不上**‌
   检查是否启动了Zookeeper，`application.yml`中的地址是否正确
2. ‌**找不到服务**‌
   确认`@DubboService`和`@DubboReference`在正确的包路径下，且`scan.base-packages`配置正确
3. ‌**端口冲突**‌
   如果启动报端口被占用，修改`dubbo.protocol.port`为其他值（如20881）



## ③直连模式

‌**Dubbo支持「直连模式」绕过注册中心**‌，这种方式适用于开发测试或简单场景。以下是实现要点和注意事项：

------

### ‌**▌ 直连模式核心原理**‌

1. ‌**跳过注册中心**‌
   服务提供者直接暴露IP和端口，消费者通过‌**硬编码URL**‌连接服务（类似直接拨打电话号码，无需查通讯录）‌
2. ‌**服务发现机制失效**‌
   需手动维护服务地址列表，无法自动感知节点上下线‌

------

### ‌**▌ 配置步骤（以Spring Boot为例）**‌

1. ‌**服务提供者配置**‌
   在`application.yml`中‌**删除注册中心配置**‌，仅保留协议和端口：

   ```yml
   dubbo:
     protocol:
       name: dubbo
       port: 20880  # 服务暴露端口
   ```

2. ‌**消费者硬编码直连**‌
   在消费者端通过`@DubboReference`指定URL：

   ```java
   @DubboReference(url = "dubbo://192.168.1.100:20880/com.example.UserService")
   UserService userService;
   ```

   ▶ 支持多个地址用分号分隔：`url="dubbo://IP1:端口;dubbo://IP2:端口"`‌
