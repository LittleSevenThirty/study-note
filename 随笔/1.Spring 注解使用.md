## Spring Boot注解

### @Autowired - ‌[Spring Framework]

- ‌**作用**‌：自动注入依赖对象（Bean）。

- ‌**功能**：

  - 默认按类型（`byType`）查找 Bean 并注入。
  - 可结合 `@Qualifier` 按名称（`byName`）注入。

- ‌**示例‌**：

  ```java
  @Autowired
  private UserService userService;
  ```



### @Bean - ‌[Spring Framework]

- ‌**作用**‌：显式声明一个 Spring Bean。

- ‌**功能**：

  - 用在 `@Configuration` 类的方法上，返回值作为 Bean。
  - 可指定 Bean 名称（如 `@Bean("myBean")`）。

- ‌**示例**：

  ```java
  javaCopy Code
  @Configuration
  public class AppConfig {
      @Bean
      public DataSource dataSource() { ... }
  }
  ```



### @Component - ‌[Spring Framework]

- ‌**作用**‌：标记一个类为 Spring 组件，由容器自动扫描并创建 Bean。

- ‌**功能**‌：

  - 通用组件注解，是 `@Service`、`@Repository`、`@Controller` 的元注解。

- ‌**示例**：

  ```Java
  @Component
  public class UserService { ... }
  ```



### @ComponentScan - ‌[Spring Framework]

- ‌**作用**‌：指定 Spring 扫描 Bean 的包路径。

- ‌**功能**‌：

  - 用在 `@Configuration` 类上，默认扫描当前包及其子包。
  - 支持自定义包路径（如 `@ComponentScan("com.example")`）。

- ‌**示例**：

  ```Java
  javaCopy Code
  @Configuration
  @ComponentScan("com.example")
  public class AppConfig { ... }
  ```



### @ConditionalOnClass - ‌[Spring Boot]

- ‌**作用**‌：条件注解，当类路径存在指定类时生效。

- ‌**功能**：

  - 常用于 Starter 模块，确保依赖存在时才启用自动配置。

- ‌**示例**：

  ```java
  
  @ConditionalOnClass(StarterService.class) // 当 StarterService 类存在时生效
  ```

------

### @ConditionalOnMissingBean - ‌[Spring Boot]

- ‌**作用**‌：条件注解，当容器中不存在指定类型的 Bean 时生效。

- ‌**功能**：

  - 避免覆盖用户自定义的 Bean。

- ‌**示例**：

  ```Java
  javaCopy Code
  @Bean
  @ConditionalOnMissingBean // 如果用户没定义 DataSource，则创建默认 Bean
  public DataSource dataSource() { ... }
  ```

------

### @ConditionalOnProperty - ‌[Spring Boot]

- ‌**作用**‌：条件注解，根据配置文件属性值决定是否生效，或者说根据参数的信息找配置文件里的值是否对应上，对应上则执行后面的函数

- ‌**功能‌**：

  - 用于按配置开启或关闭功能。

- ‌**示例**：

  ```java
  javaCopy Code
  @ConditionalOnProperty(prefix = "app", name = "enabled", havingValue = "true")
  ```

* **参数：**
  * prefix：在配置文件里某条属性前的所有前缀，在上述例子里就是 app.enabled属性的前缀 app
  * name：（必填）在配置文件里对应某条属性，加上前缀后就会与配置文件的属性相对照
  * havingValue：对应属性期望的值，若相等，则此注解允许你执行下面的代码，否则就不允许
  * matchIfMissing：如果配置文件没有对应属性，那么是否也允许执行后面代码，默认false就是不允许，若改为true则就算前面都不成立也会执行后面代码

### @Configurable

**作用：**为`new`关键字创建的对象提供依赖注入能力，让 ‌**new 出来的对象**‌ 也能自动注入 Spring 管理的依赖项。比如你有个类 `UserService`，用 `new UserService()` 创建实例时，里面的 `@Autowired` 字段会自动被 Spring 填充‌

**依赖：**

* `spring-aspects`（提供字节码增强支持）
* `aspectjweaver`（AspectJ运行时）

**生效条件：**

* 启用`@EnableSpringConfigured`
* 配置`AnnotationBeanConfigurerAspect`切面
* 使用编译时或加载时织入（CTW/LTW）



### @Configuration - ‌[Spring Framework]

- ‌**作用**‌：声明一个类为配置类，替代 XML 中对Bean的配置，最主要的是BeanId配置。

- ‌**功能**：

  - 内部通过 `@Bean` 方法定义 Bean。
  - 默认使用 CGLIB 代理，确保 `@Bean` 方法调用返回单例。

- ‌**示例**：

  ```java
  @Configuration
  public class AppConfig { ... }
  ```

### @ConfigurationProperties

@ConfigurationProperties注解常常和@Configuration注解以及@EnableConfigurationProperties搭配，

官方文档建议将配置属性隔离到单独的 POJO 中。

如下：

```java
@Configuration
@ConfigurationProperties(prefix = "mail")
public class ConfigProperties {
    
    private String hostName;
    private int port;
    private String from;

    //Get、Set 方法
}
```

通过 `@Configuration` 注解，Spring 会在 Application Context 中创建一个 Spring Bean。

`@ConfigurationProperties` 最适合具有相同前缀的分层属性，这里添加了一个名为 `mail` 的前缀。

Spring 框架使用标准的 Java Bean Setter，因此必须为每个属性声明 Setter 方法。

注：如果不在 POJO 中使用 `@Configuration`，则需要在 Spring `Application` *main* 类中添加 `@EnableConfigurationProperties(ConfigProperties.class)` 以将属性绑定到 POJO 中：

```java
@SpringBootApplication
@EnableConfigurationProperties(ConfigProperties.class)
public class EnableConfigurationDemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(EnableConfigurationDemoApplication.class, args);
    }
}
```

如上！Spring 会自动绑定属性文件中定义的、前缀为 `mail` 且名称与 `ConfigProperties` 类中某个字段相同的任何属性。

Spring 对绑定属性使用了一些宽松的规则。因此，以下各种变体都可以绑定到属性 `hostName`：

```properties
mail.hostName
mail.hostname
mail.host_name
mail.host-name
mail.HOST_NAME
```

可以使用下面的 properties 文件来设置所有字段：

```properties
# 示例 properties
mail.hostname=host@mail.com
mail.port=9000
mail.from=mailer@mail.com
```

<font color=red>简单说，就是当IOC实例化ConfigProperties对象时，会根据@ConfigurationProperties的prefix属性匹配配置文件的前缀后将对应属性值赋值给该对象</font>



### @Controller

**作用：**标记一个类为Spring MVC控制器，定义请求路由规则，绑定请求参数和返回响应等

**功能：**处理HTTP请求，协调业务逻辑和视图渲染，通过组合注解（如`@GetMapping`, `@PostMapping`）将URL映射到具体方法，接收请求参数（`@RequestParam`, `@PathVariable`），返回视图名或数据模型

**示例：**

```java
@Controller // 声明这是一个控制器
public class HelloController {
    
    // 处理GET请求 /hello?name=xxx
    @GetMapping("/hello")
    public String sayHello(
        @RequestParam(name = "name", defaultValue = "World") String name,
        Model model // 数据模型，用于向视图传递数据
    ) {
        // 将参数添加到模型
        model.addAttribute("message", "Hello, " + name + "!");
        // 返回视图名（对应src/main/resources/templates/hello.html）
        return "hello"; 
    }
}
```



### @CrossOrigin

**作用：**
解决跨域请求限制，允许不同域的前端应用访问后端API接口（常用于前后端分离架构）

**核心属性：**

| 属性    | 功能                                                         |
| ------- | ------------------------------------------------------------ |
| origins | 指定允许的域名列表（例如origins={"http://domain1.com","http://domain2.com"},`"*"`表示允许所有源 |
| methods | 支持的HTTP方法（如Get、Post）                                |
| maxAge  | 预检请求缓存时间（秒），减少重复预检请求                     |

**示例：**

```java
@RestController
@CrossOrigin(origins = "*", methods = {RequestMethod.GET, RequestMethod.POST})
public class MyController {
    // 控制器方法
}
```



### @DependsOn

**作用：**显示声明Bean的初始化顺序，确保依赖的 Bean 优先初始化

**功能：**当 Bean 之间没有直接依赖（如未通过`@Autowired`注入），但初始化逻辑需要其他Bean已存在时，该注解会优先检查是否所需Bean已实例化

**<font color=red>注意：</font>**依赖的Bean名称（ID）需要与Spring容器中注册的名称完全一致

**示例：**
被依赖的Bean注册方式：
①通过@Configuration标记的配置类显示定义

```java
@Configuration
public class AppConfig {

    // 通过 @Bean 显式定义，Bean 名称为方法名 "openai_model"
    @Bean
    public OpenAIModel openai_model() {
        return new OpenAIModel("gpt-4");
    }
	...
}
```

②通过@Component，@Service，@Controller注册的Bean，<font color=red>value值就是Bean 名称/ID</font>

```java
// 以下为组件类，也可用 @Component 替代 @Bean
@Component(value="openai_model")
class OpenAIModel {
    private String modelName;
    public OpenAIModel(String modelName) {
        this.modelName = modelName;
        System.out.println("OpenAIModel 初始化完成: " + modelName);
    }
}

// 同样是组件类，不显示定义其value
@Component
class OpenAIUsageCount {
    public OpenAIUsageCount() {
        System.out.println("OpenAIUsageCount 初始化完成");
    }
}
...
```

依赖使用：

```java
import org.springframework.context.annotation.DependsOn;
import org.springframework.stereotype.Service;
import javax.annotation.PostConstruct;

@Service
@DependsOn(value = {"openai_model", "opeanai_use_count", "user_credit_random"})
public class OpenAIService {

    @PostConstruct
    public void init() {
        System.out.println("OpenAIService 初始化完成（依赖已就绪）");
        // 实际业务中可在此访问依赖的Bean
    }
}
```

### **@ImportResource**‌

**作用**

- ‌**导入XML配置**‌：将类路径下的XML配置文件（如`classpath:spring/spring.xml`）加载到Spring应用上下文中，使XML中定义的Bean能够被Spring容器管理。
- ‌**兼容旧项目**‌：适用于需要保留历史遗留的XML配置的项目，同时结合Java配置类使用。

**功能**

- ‌**位置**‌：通常放在Java配置类（`@Configuration`类）或主应用类（如Spring Boot的`@SpringBootApplication`类）上。
- ‌**路径格式**‌：支持类路径（`classpath:`）、文件系统（`file:`）或URL路径。

**示例**

```
@Configuration
@ImportResource("classpath:spring/spring.xml") // 导入XML配置
public class AppConfig {
    // 其他Java配置...
}
```

**注意事项**

- XML和Java配置的Bean名称冲突时，默认Java配置优先（取决于加载顺序）。
- 推荐逐步迁移到Java配置，减少XML的使用



### @Order

**作用：**控制Bean加载或集合中的顺序

**作用范围：**类级别或方法级别，**如果同时出现@Order和@Primary优先Primary，再使用Order内的顺序**

**示例：**

验证处理器定义

```java
// ValidationHandler.java
public interface ValidationHandler {
    void validate(String data);
}

// LengthValidation.java
@Component
@Order(1)  // 最高优先级
public class LengthValidation implements ValidationHandler {
    @Override
    public void validate(String data) {
        System.out.println("执行长度校验: " + data.length());
    }
}

// FormatValidation.java
@Component
@Order(2)
public class FormatValidation implements ValidationHandler {
    @Override
    public void validate(String data) {
        System.out.println("执行格式校验: " + data.matches(".*"));
    }
}
```

集合注入点

```java
// ValidationService.java
@Component
public class ValidationService {
    private final List<ValidationHandler> handlers;

    @Autowired  // 自动按@Order顺序注入
    public ValidationService(List<ValidationHandler> handlers) {
        this.handlers = handlers;
    }

    public void runValidation(String data) {
        handlers.forEach(h -> h.validate(data));
    }
}
```



### @PostConstruct

**作用：**在所有依赖注入完成后、Bean初始化阶段后执行

**执行条件：**需要CommonAnnotationBeanPostProcessor（Spring Boot自动配置）

**方法规范：**

* 方法必须void返回类型
* 不能有参数
* 允许抛出异常（可能导致Bean初始化失败）



### @PreDestroy

**作用：**用于标记在Bean示例被销毁之前需要执行的方法

**适用场景：**释放资源（如关闭数据库连接、清理临时文件等）

**触发时间：**当Spring容器关闭时（如调用`context.close()`，单例Bean的`@PreDestroy`方法会被调用，原型(prototype)Bean的销毁方法不会自动出发，需手动管理

**示例：**

```java
import javax.annotation.PreDestroy;
import org.springframework.stereotype.Component;

@Component // 声明为Spring管理的Bean
public class DatabaseConnection {

    public DatabaseConnection() {
        System.out.println("DatabaseConnection constructed.");
    }

    // 销毁前执行的方法
    @PreDestroy
    public void close() {
        System.out.println("DatabaseConnection closing resources...");
    }
}

```

**<font color=red>Bean生命周期流程：</font>**

>实例化Bean → 依赖注入 → @PostConstruct → Bean就绪 → @PreDestroy



### @Primary

**作用：**解决相同类型Bean的注入冲突问题（一般都是一个接口有多个实现类需要被注册，或抽象父类的多个子继承问题）
**作用范围：**单个Bean定义级别

**示例：**

①组件定义

```java
public interface DatabaseConfig{
    String getConfig();
}

// MySQLConfig.java
@Component
@Primary	// 被标记为默认实现
public class MySQLConfig implements DatabaseConfig{
        @Override
    public String getConfig() {
        return "MySQL Configuration";
    }
}
// PostgreSQLConfig.java
@Component
public class PostgreSQLConfig implements DatabaseConfig {
    @Override
    public String getConfig() {
        return "PostgreSQL Configuration";
    }
}
```

②注入点

```java
// DataService.java
@Component
public class DataService {
    private final DatabaseConfig config;

    @Autowired  // Autowired自动根据类名匹配自动选择@Primary标注的Bean
    public DataService(DatabaseConfig config) {
        this.config = config;
    }

    public void printConfig() {
        System.out.println("当前配置: " + config.getConfig());
    }
}
```



### @Profile

**作用：**用于根据**运行环境**动态激活不同的Bean实现，使用场景包括

* **环境隔离：**生产环境（prod）、测试环境（test）使用不同的配置或组件
* **按需加载：**避免在非目标环境中加载不必要的Bean，节省资源

**代码示例：**

```java
// 定义数据源接口
public interface DataSource {
    String connect();
}

// 生产环境实现类
@Component
@Profile("prod") // 仅在 prod 环境激活
class ProdDataSource implements DataSource {
    @Override
    public String connect() {
        return "连接到生产数据库";
    }
}

// 测试环境实现类
@Component
@Profile("test") // 仅在 test 环境激活
class TestDataSource implements DataSource {
    @Override
    public String connect() {
        return "连接到测试数据库";
    }
}
```

**如何激活**：

①通过配置文件application.yml/application.properties激活

```yaml
# 激活 prod 环境
spring.profiles.active=prod

# 或者激活多个环境（逗号分隔）
spring.profiles.active=prod,test
```

②通过JVM参数启动

```bash
java -jar your-app.jar -Dspring.profiles.active=test
```

③通过环境变量设置

```bash
export SPRING_PROFILES_ACTIVE=prod
java -jar your-app.jar
```



### @PropertySource

* **作用：**该注解用于加载指定的属性文件（如`.propterties`或`.yml`）中的键值对注入到Spring应用的`Environment`中，方便通过`@Value`或`Enviroment`对象获取配置，**通常标注在配置类(`@Configuration`)上**
* **功能：**将属性文件的键值对注入到应用环境里

* **示例：**

```prop
app.name=zql-frame-spring-dependency-injection-study
app.version=1.0.0
```

```java
@Slf4j
@SpringBootApplication
@Configurable
@PropertySource("classpath:propterties/application.properties")
@ImportResource("classpath:spring/spring.xml")
@EnableScheduling
public class Application {
    public static void main(String[] args){
        SpringApplication.run(Application.class);
    }
}
```

<font color=red>注意：`classpath`表示资源目录(`src/main/resources`)</font> 

<font color=red>注意2：默认会加载application.yml或properties文件，如果存在profile文件，也会对应加载附件application-prod/dev/pro等</font> 

* **注入属性：**
  * ‌**通过`@Value`注解**‌：

```java
@Value("${app.name}")
private String appName;
```

* **通过`Environment`对象**‌：

```java
@Autowired
private Environment env;
String appName = env.getProperty("app.name");
```

**3. 高级配置**‌

- ‌多文件加载：

  ```java
  @PropertySource({"classpath:common.properties", "classpath:app.properties"})
  ```

- ‌忽略不存在的文件：

  ```java
  @PropertySource(value = "classpath:config.properties", ignoreResourceNotFound = true)
  ```

- ‌指定编码处理中文乱码：

  ```java
  @PropertySource(value = "classpath:config.properties", encoding = "UTF-8")
  ```

- ‌加载外部文件‌：

  ```java
  @PropertySource("file:/etc/myapp/config.properties") // 文件系统路径
  ```

  



### @Repository

**作用：**‌标识DAO层组件，自动注册为Spring Bean，‌异常转换

**功能：**明确标记数据访问层（Data Access Object）类，实现数据库操作逻辑的封装，通过组件扫描（`@ComponentScan`）被Spring容器管理，支持依赖注入 ，将数据访问层抛出的原生异常（如JDBC/SQL异常）转换为Spring统一的`DataAccessException`，便于统一处理

**示例：**

```java
@Repository // 标记为DAO层组件 ‌:ml-citation{ref="1,5" data="citationList"}
public class UserDao {
    // 模拟数据库操作
    public User findUserById(Long id) {
        // 实际场景中可能使用JdbcTemplate、JPA或MyBatis等工具
        return new User(id, "张三", "zhangsan@example.com");
    }
}
```

### @Scope

**中文解释：范围**

**作用：**用于定义Spring Bean的作用域，即Bean的生命周期和创建规则，常见作用域有：

| 作用域类型    | 描述                                                       |
| ------------- | ---------------------------------------------------------- |
| `singleton`   | 默认作用域，单例模式，容器中只存在一个实例，所有请求共享。 |
| `prototype`   | 原型模式，每次请求都创建新实例。                           |
| `request`     | 每个HTTP请求创建一个新实例（需Web环境）。                  |
| `session`     | 每个HTTP会话创建一个新实例（需Web环境）。                  |
| `application` | 类似ServletContext生命周期，整个Web应用共享。              |

**示例：**

```java
// 配置类：定义Bean的作用域和扫描路径
@Configuration
@ComponentScan(basePackages = "com.example")
public class AppConfig {

    @Bean
    @Scope("prototype") // 显式声明原型作用域
    public PrototypeBean prototypeBean() {
        return new PrototypeBean();
    }
}

// Singleton作用域Bean（默认）
@Component
public class SingletonBean {
    public void doWork() {
        System.out.println("SingletonBean实例: " + this.hashCode());
    }
}

// Prototype作用域Bean
@Component
@Scope(value = "prototype") // 或@Scope("prototype")
public class PrototypeBean {
    public void doWork() {
        System.out.println("PrototypeBean实例: " + this.hashCode());
    }
}
```



### @Service

**作用：**标记一个类为服务层组件，自动注册为Spring Bean，代码分层标识，无特殊功能，但语义明确

**功能：**标识该类属于业务逻辑层，通常包含核心业务规则和事务管理，通过组件扫描被Spring容器管理，支持依赖注入，与`@Controller`（控制层）、`@Repository`（数据层）配合，明确架构层次，功能与`@Component`相同，但用于提高代码可读性（标识服务层职责）

**示例：**

```java
import org.springframework.stereotype.Service;

@Service // 标记为服务层组件
public class UserService {
    
    // 模拟业务方法：保存用户
    public void saveUser(String username, String email) {
```

### @SpringBootTest

- ‌**作用：**‌
  标记一个类为 Spring Boot 集成测试的入口，用于启动完整的应用程序上下文环境，支持依赖注入、组件扫描和配置加载，以模拟真实运行环境下的端到端测试。
- ‌**功能：**‌
  1. 自动加载主配置类（`@SpringBootApplication` 标注的类）及其关联的所有 Bean。
  2. 支持通过参数（如 `classes`、`properties`）自定义测试配置，覆盖默认配置。
  3. 提供 Web 环境模式（如 `MOCK`、`RANDOM_PORT`）以测试 Web 层（如 Controller）。
  4. 集成 JUnit 5 测试框架（需配合 `@ExtendWith(SpringExtension.class)`，但 Spring Boot 已隐式包含）。
- ‌**示例：**‌

```java
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)  
public class MyApplicationTests {  
    @Autowired  
    private UserService userService;  

    @Test  
    public void testService() {  
        User user = userService.findById(1L);  
        assertNotNull(user);  
    }  
}  
```
