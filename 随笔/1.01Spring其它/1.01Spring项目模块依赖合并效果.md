# Spring项目模块依赖合并效果

模块依赖的合并效果总结
1. **‌核心机制‌**
类路径合并‌：
当 `app `主模块通过 `pom.xml `依赖` infrastructure` 子模块时，编译打包后，`infrastructure `中的 .class 文件会被合并到 app 模块的类路径（target/classes 或打包后的 JAR）中。
**Spring 视角‌：合并后，Spring 会将所有类视为同一项目的一部分，不会区分代码来自哪个模块。**
2. ‌**包路径规则‌**

**父子包关系‌：**
Spring 默认扫描主类所在包及其所有子包。若 infrastructure 中的类包路径是主类所在包的‌子包‌，则自动扫描生效。

**示例‌：**
主类包：com.example.app
DAO 类包：com.example.app.infrastructure.dao ✅
（子包结构会被自动扫描到）

**非父子包关系‌：**
若 infrastructure 的包路径与主类包无关（如 com.example.infrastructure），则‌需要显式配置‌ @ComponentScan。

3. **‌实际项目中的典型场景‌**
  DDD 架构示例‌：
  text

  ```cmd
  app模块（主类）包路径：com.example.app  
  infrastructure模块包路径：com.example.app.infrastructure（子包）  
  ```

结果‌：即使没有 @ComponentScan，infrastructure 中的 @Repository 也会被自动扫描注册。
4. ‌**底层原因‌**
Spring 的默认行为‌：
@SpringBootApplication 注解隐式包含 @ComponentScan，且默认扫描范围为‌主类所在包及其子包‌。
模块依赖只是物理合并类路径‌，真正决定是否扫描的是包路径的父子关系。
5. ‌注意事项‌
  包层级必须严格匹配‌：
  即使模块依赖存在，若包路径不符合父子关系（如主类在 com.example.app，DAO 在 com.example.infra），仍需手动配置扫描。
  IDE 编译行为‌：
  IDEA 等工具在开发时会将依赖模块的代码视为同一项目，可能掩盖包路径错误，但‌打包部署时仍需确保包路径正确‌。
  总结图示

  ```txt
  模块依赖（物理合并） → 类路径统一 → Spring 按包路径规则扫描 → 自动注册
  ```


关键因素‌：模块依赖 + 包路径父子关系。
