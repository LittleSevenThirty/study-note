# **Sass变量**
### 1. 宏观背景：为什么要用变量？
在 CSS 中，我们经常面临“魔法数字”的困扰——同一个颜色值（如 `#005f73`）在代码中重复出现数十次。如果产品经理突然说“把这个蓝色调深一点”，你将面临一场手动替换的噩梦。

**Sass 变量就是来解决这个问题的**。它允许你将值（颜色、尺寸、字体等）存储在一个容器中，通过引用容器名来使用值。但 Sass 变量不仅仅是“查找替换”，它还包含作用域、默认值配置等高级机制，是构建大型样式库（如 Bootstrap）的必备工具。

---

### 2. 详尽笔记（核心部分）

#### 知识点 A：基础语法与核心特性
Sass 变量以 **`$` 符号**开头，后跟变量名和值（例如 `$primary-color: blue;`）。与 CSS 属性不同，变量可以在样式表的任何位置声明（不仅限于选择器内部）。

**关键特性：连字符与下划线互通**
这是一个历史遗留的“坑”与“特性”。Sass 最初只支持下划线，后来为了兼容 CSS 的连字符习惯，将两者视为等同。这意味着 `$font_size` 和 `$font-size` 指的是同一个变量。

**辅助实例：**
```scss
// 声明
$base-color: #c6538c;
$border-dark: rgba($base-color, 0.88); // 变量可以嵌套引用

// 使用
.alert {
  border: 1px solid $border-dark;
}
```

#### 知识点 B：Sass 变量 vs CSS 变量（核心差异）
这是文档中极其重要的一段对比，混淆这两者是新手常犯的错误。

*   **Sass 变量（命令式）**：在编译阶段就被替换成了具体的 CSS 值。它在浏览器中是“看不见”的，且一个变量在编译时只能有一个值。
*   **CSS 变量（声明式）**：保留在最终的 CSS 文件中，由浏览器在运行时解析。它支持继承，不同元素可以有不同的值。

**辅助实例：**
```scss
// Sass 变量是“死”的
$variable: value 1;
.rule-1 { value: $variable; } // 编译后直接变成 value: value 1

$variable: value 2; // 重新赋值
.rule-2 { value: $variable; } // 编译后变成 value: value 2
// 注意：.rule-1 的值不会因为后面的重新赋值而改变
```

#### 知识点 C：默认值（!default）与库配置
这是 Sass 变量最强大的功能，主要用于**库开发**。通常赋值会覆盖旧值，但加上 `!default` 后，只有当变量**未定义**或值为 **`null`** 时，才会赋予新值。

**应用场景**：作为库作者，你希望用户能自定义主题色，但如果你的库内部代码直接赋值，就会覆盖用户的设置。使用 `!default` 可以完美解决这个冲突。

**辅助实例：**
*   **库文件 (`_library.scss`)**：
    ```scss
    $black: #000 !default;
    $border-radius: 0.25rem !default;
    code { border-radius: $border-radius; }
    ```

*   **用户配置 (`style.scss`)**：
    ```scss
    @use 'library' with (
      $black: #222,
      $border-radius: 0.1rem
    );
    ```
    **结果**：用户配置的值覆盖了库中的默认值，实现了“主题定制”。

#### 知识点 D：作用域（Scope）与阴影（Shadowing）
Sass 遵循标准的编程语言作用域规则，但也有一些特殊细节。

*   **全局作用域**：在文件顶层声明。
*   **局部作用域**：在 `{}` 代码块内声明，默认只能在块内访问。
*   **变量阴影**：局部变量可以和全局变量同名。此时，局部变量会“遮蔽”全局变量，两者互不干扰。
*   **强制全局（!global）**：在局部块内使用 `!global` 标志，可以强制修改全局变量的值。

**辅助实例：**
```scss
$variable: global value;

.content {
  $variable: local value; // 声明局部变量
  value: $variable; // 输出: local value (局部遮蔽了全局)
}

.sidebar {
  value: $variable; // 输出: global value (局部变量已失效)
}
```

#### 知识点 E：流程控制中的特殊作用域
在 `@if`、`@for` 等控制流规则中声明的变量，行为比较特殊。它们**不会**创建新的局部作用域，而是直接赋值给外部同名变量。

**注意点**：如果你想在控制流中修改变量，该变量必须在外部提前声明（哪怕是 `null`），否则控制流结束后变量将不可访问。

**辅助实例：**
```scss
$dark-theme: true !default;
$primary-color: null; // 必须先声明

@if $dark-theme {
  $primary-color: #333; // 直接修改外部变量
}

.button { color: $primary-color; } // 可以访问到 #333
```

#### 知识点 F：动态变量与映射（Map）
Sass **不允许**通过插值（`#{}`）来动态创建变量名（例如 `$#{$name}`），因为这会让代码变得难以追踪（不知道变量在哪定义的）。

**替代方案**：使用 **Map（映射）** 数据结构。Map 是一个键值对集合，你可以通过变量作为 Key 来获取值。

**辅助实例：**
```scss
// 定义映射
$theme-colors: (
  "success": #28a745,
  "info": #17a2b8,
  "warning": #ffc107
);

// 错误做法：$theme-color-#{warning} (不支持)
// 正确做法：使用 map.get()
.alert {
  background-color: map.get($theme-colors, "warning");
}
```

### 3. 补充细节（关键注意事项）

1.  **!global 的新限制**：
    在现代 Dart Sass (2.0.0+) 中，`!global` 标志只能用于修改**已存在**的全局变量，不能在局部块内用它来声明一个全新的全局变量。

2.  **内置变量不可修改**：
    由内置模块（如 `sass:math`）定义的变量（如 `$pi`）是常量，不能被重新赋值。

3.  **变量存在性检查**：
    你可以使用 `meta.variable-exists($name)` 来检查当前作用域是否存在某个变量，或者用 `meta.global-variable-exists()` 检查全局变量。

4.  **配置模块的兼容性**：
    使用 `@use ... with` 语法来配置变量仅在 **Dart Sass 1.23.0+** 版本中支持，旧版 LibSass 和 Ruby Sass 不支持此功能。

---

### 4. 关键启发/总结

1.  **配置优先原则**：
    如果你正在编写一个 Sass 库供他人使用，请务必给所有可配置的变量加上 `!default`。这是 Sass 社区约定俗成的标准，它能让使用者通过 `@use ... with` 轻松定制主题，而无需修改你的源代码。

2.  **Map 是数据管理的终极方案**：
    当你需要处理一组相关的值（如颜色体系、断点设置）时，不要试图去“hack”动态变量名，而是拥抱 **Map**。结合 `map.get()` 函数，它可以完美模拟“变量数组”的功能。

3.  **区分编译时与运行时**：
    牢记 Sass 变量是**编译时**的工具。它在构建阶段就已经完成了值的替换。如果你需要在网页运行时通过 JavaScript 动态改变样式（例如用户点击切换主题），你应该使用原生 CSS 变量（Custom Properties），而不是 Sass 变量。
