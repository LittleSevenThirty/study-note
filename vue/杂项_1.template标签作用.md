# 📝 Vue 中的 `<template>` 标签详解笔记

> ✅ 适用场景：Vue 3 + `<script setup>`  
> 📚 官方虽未单独强调，但它贯穿条件渲染、列表、插槽等核心功能

---

## 一、`<template>` 是什么？

- **它是 HTML5 的原生标签**（不是 Vue 发明的！）
- **作用**：作为**不可见的包裹容器**，用于分组多个元素，但**自身不会被渲染到 DOM 中**
- **类比**：像 Word 文档里的“无格式文本框”——内容会显示，但框本身看不见

---

## 二、为什么需要 `<template>`？

### 问题场景：
你想根据条件显示 **两段文字**：

```html
<!-- ❌ 错误：v-if 不能同时作用于两个兄弟元素 -->
<p v-if="show">第一段</p>
<p v-if="show">第二段</p>
```

但这样写：
- 重复写 `v-if`
- 如果逻辑复杂，难以维护
- 更糟的是：**无法保证原子性**（比如过渡动画会分别触发）

👉 这时就需要 `<template>` 来“隐形打包”！

---

## 三、`<template>` 的核心用途（Vue 中）

### 1. 作为“逻辑包裹器”（不渲染自身）

#### ✅ 示例：条件渲染多元素
```vue
<template v-if="isLoggedIn">
  <h1>欢迎回来！</h1>
  <p>你的积分：100</p>
  <button @click="logout">退出</button>
</template>
<template v-else>
  <h1>请登录</h1>
  <LoginForm />
</template>
```

✅ 渲染结果（当 `isLoggedIn = true`）：
```html
<h1>欢迎回来！</h1>
<p>你的积分：100</p>
<button>退出</button>
<!-- 注意：<template> 自己消失了！ -->
```

> 💡 **关键特性**：`<template>` 永远不会出现在最终 DOM 中，只作为 Vue 的“编译期占位符”

---

### 2. 配合 `v-for` 渲染多节点

```vue
<ul>
  <template v-for="item in items" :key="item.id">
    <li>{{ item.title }}</li>
    <li class="divider"></li>
  </template>
</ul>
```

✅ 渲染结果：
```html
<ul>
  <li>标题1</li>
  <li class="divider"></li>
  <li>标题2</li>
  <li class="divider"></li>
</ul>
```

> ⚠️ 注意：`key` 必须放在 `<template>` 上（Vue 3.4+ 支持），而不是内部元素

---

### 3. 插槽（Slots）的载体（最重要！）

在具名插槽或作用域插槽中，**必须用 `<template>` 包裹内容**：

```vue
<BaseLayout>
  <!-- ✅ 正确：用 template 指定插槽名 -->
  <template #header>
    <h1>我的网站</h1>
  </template>

  <!-- ✅ 作用域插槽也必须用 template -->
  <template #default="{ user }">
    <p>Hello, {{ user.name }}!</p>
  </template>
</BaseLayout>
```

> ❌ 不能这样写（会报错或行为异常）：
> ```vue
> <BaseLayout>
>   <h1 #header>错误！</h1> <!-- 语法非法 -->
> </BaseLayout>
> ```

---

### 4. 在 `<script setup>` 中定义组件模板

每个单文件组件（`.vue`）的根必须是 `<template>`：

```vue
<!-- MyComponent.vue -->
<template>
  <div>这是组件内容</div>
</template>

<script setup>
// 组合式逻辑
</script>
```

> ✅ 这是 SFC（单文件组件）的固定结构要求

---

## 四、`<template>` vs `<div>` —— 关键区别

| 特性 | `<template>` | `<div>` |
|------|--------------|--------|
| 是否渲染到 DOM | ❌ 不渲染 | ✅ 渲染为真实元素 |
| 能否加 class/style | ❌ 无效（因为不渲染） | ✅ 可以 |
| 能否加 key/v-if/v-for | ✅ 可以（作为指令载体） | ✅ 可以 |
| 是否影响 CSS 布局 | ❌ 无影响 | ✅ 可能破坏布局（如 flex/grid） |
| 插槽中是否必需 | ✅ 是（指定插槽名） | ❌ 否 |

### 🌰 举例：避免多余 div 破坏布局

```vue
<!-- 使用 div 会导致 ul 结构错误 -->
<ul>
  <div v-for="item in list" :key="item.id">
    <li>{{ item }}</li>
  </div>
</ul>
<!-- 渲染为：<ul><div><li>...</li></div></ul> → ❌ 非法 HTML -->

<!-- 使用 template 保持结构正确 -->
<ul>
  <template v-for="item in list" :key="item.id">
    <li>{{ item }}</li>
  </template>
</ul>
<!-- 渲染为：<ul><li>...</li></ul> → ✅ 合法 -->
```

## 五、常见误区 & 注意事项

| 误区 | 正确理解 |
|------|--------|
| ❌ “`<template>` 是 Vue 特有的” | ✅ 它是标准 HTML5 标签，Vue 只是利用了它的“不渲染”特性 |
| ❌ “可以在 `<template>` 上加 class” | ❌ 加了也没用，因为它不出现在 DOM 中 |
| ❌ “`<template>` 可以有多个根节点” | ✅ 在 Vue 3 中，组件模板确实支持多根节点（Fragment），但通常仍建议用 `<template>` 显式包裹逻辑块 |
| ❌ “插槽内容可以直接写在组件标签里不用 template” | ✅ **仅限默认插槽且无其他具名插槽时**；一旦有具名插槽，必须用 `<template #xxx>` |

---

## 六、一句话总结

> **`<template>` 是 Vue 中的“隐形胶带”——它能把多个元素绑在一起做条件判断、循环或插槽传递，但自己永远不会出现在页面上，从而保持 DOM 结构干净、语义正确。**
