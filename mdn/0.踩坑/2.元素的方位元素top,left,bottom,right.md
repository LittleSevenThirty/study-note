你现在的困惑核心是没搞懂 `getBoundingClientRect()` 返回的 `top/bottom/left/right` 这些方位属性的含义，以及这段 `rect.top - 100 > window.innerHeight` 代码到底在判断什么——这其实是前端判断「元素是否在视口可见」的核心逻辑，我用「可视化+通俗解释+代码拆解」的方式帮你彻底搞懂。

### 第一步：先搞懂「视口坐标系」（理解这些属性的基础）
`getBoundingClientRect()` 的所有方位属性（top/bottom/left/right），都是基于**浏览器视口的坐标系**来计算的，先记住这个坐标系的规则：
- 📌 原点（0,0）：在浏览器视口的**左上角**
- 📌 水平方向（X轴）：向右为正方向
- 📌 垂直方向（Y轴）：向下为正方向

用一张「文字示意图」帮你直观理解：
```
视口（window.innerHeight 是视口高度）
+-----------------------------------------+  Y=0（视口上边缘）
| （0,0）→ X轴向右                        |
|                                        |
| 元素的top：元素上边缘到Y=0的距离         |
|  ┌-------------------┐                  |
|  │ 元素              │                  |
|  │                   │ 元素的bottom：元素下边缘到Y=0的距离
|  └-------------------┘                  |
|                                        |
|                                        |
+-----------------------------------------+  Y=window.innerHeight（视口下边缘）
```

### 第二步：拆解 `getBoundingClientRect()` 的核心属性
先明确每个属性的**通俗含义**（只记核心的，其他不用管）：
| 属性       | 通俗含义（基于视口坐标系）| 举个例子（方便理解）|
|------------|---------------------------------------------|------------------------------------------|
| rect.top   | 元素**上边缘**到视口**上边缘（Y=0）** 的垂直距离 | 若top=200 → 元素上边缘在视口顶部往下200px处 |
| rect.bottom| 元素**下边缘**到视口**上边缘（Y=0）** 的垂直距离 | 若bottom=400 → 元素下边缘在视口顶部往下400px处 |
| rect.left  | 元素**左边缘**到视口**左边缘（X=0）** 的水平距离 | 若left=100 → 元素左边缘在视口左侧往右100px处 |
| rect.right | 元素**右边缘**到视口**左边缘（X=0）** 的水平距离 | 若right=300 → 元素右边缘在视口左侧往右300px处 |
| rect.width | 元素实际宽度（right - left），精准到小数      | 比如rect.right=300、left=100 → width=200 |
| rect.height| 元素实际高度（bottom - top），精准到小数     | 比如rect.bottom=400、top=200 → height=200 |

⚠️ 关键补充：
- 如果元素在视口**上方**（比如没滚动到），`rect.top` 会是**负数**（比如top=-100 → 元素上边缘在视口顶部往上100px处）；
- 如果元素在视口**下方**（比如还没显示出来），`rect.top` 会**大于视口高度**（比如视口高800，top=900 → 元素上边缘在视口底部往下100px处）。

### 第三步：拆解你给的代码 `rect.top - 100 > window.innerHeight`
先把代码拆成「人话」，再讲它的实际作用：

#### 1. 先拆每个部分的含义
- `window.innerHeight`：视口的高度（比如800px，就是视口从上到下的总高度）；
- `rect.top`：元素上边缘到视口上边缘的距离；
- `rect.top - 100`：给元素上边缘「预留100px的偏移量」（比如元素top=900，减100后是800）；
- `> window.innerHeight`：判断「减完偏移量后的值」是否超过视口高度。

#### 2. 整体逻辑（通俗版）
这段代码是在判断：**元素是否完全在视口下方（超出视口底部），且距离视口底部还有至少100px的距离**（还没滚动到能看到的范围）。

#### 3. 举个具体例子（一看就懂）
假设：
- 视口高度 `window.innerHeight = 800px`；
- 元素的 `rect.top = 950px`（元素上边缘在视口顶部往下950px处，已经超出视口底部800px的位置）。

计算：`950 - 100 = 850` → `850 > 800` → 返回 `true`，说明「元素还在视口下方很远的位置，暂时看不到」。

反过来，如果元素 `rect.top = 750px`：
`750 - 100 = 650` → `650 < 800` → 返回 `false`，说明「元素已经靠近视口底部，快要进入视野了」。

### 第四步：补充常见的「元素可见性判断」场景（帮你举一反三）
除了判断「元素在视口下方」，前端常用这些逻辑判断可见性，你可以对照理解：
```javascript
const rect = el.getBoundingClientRect();
const viewportHeight = window.innerHeight;
const viewportWidth = window.innerWidth;

// 1. 判断元素是否完全在视口内（常用：曝光埋点、元素可见触发动画）
const isFullyInViewport = (
  rect.top >= 0 &&        // 元素上边缘不超出视口顶部
  rect.bottom <= viewportHeight &&  // 元素下边缘不超出视口底部
  rect.left >= 0 &&       // 元素左边缘不超出视口左侧
  rect.right <= viewportWidth       // 元素右边缘不超出视口右侧
);

// 2. 判断元素是否部分在视口内（常用：懒加载、滚动加载）
const isPartInViewport = (
  rect.top < viewportHeight &&  // 元素上边缘没超出视口底部
  rect.bottom > 0              // 元素下边缘没超出视口顶部
);
```

### 总结
1. `getBoundingClientRect()` 的 `top/bottom/left/right` 都是以**视口左上角（0,0）** 为原点计算的距离，Y轴向下为正；
2. `rect.top - 100 > window.innerHeight` 核心作用是：判断元素是否在视口下方且距离底部≥100px（暂时不可见）；
3. 记住「正负值含义」：top为负→元素在视口上方，top>视口高度→元素在视口下方。

你可以把这段代码复制到浏览器控制台，找一个页面里的元素（比如`document.querySelector('div')`），打印`rect`的值，再滚动页面看`top/bottom`的变化，马上就能直观感受到这些属性的规律。
