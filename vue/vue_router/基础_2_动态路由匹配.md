# **动态路由匹配特性**

### 📚 第一章：带参数的动态路由匹配

#### **1. 核心概念：什么是路径参数？**

*   **【原文要点】**
    在开发中，我们经常需要让一个组件处理多种不同的数据。例如，一个 `User` 组件应该能显示所有用户的资料，只是用户 ID 不同。Vue Router 允许我们在路径中使用动态字段（称为“路径参数”）来实现这一点。

*   **【深度拆解】**
    *   **静态 vs 动态**：普通的路由是静态的，比如 `/about` 只能匹配 about 页面。动态路由则是 `/users/:id`，这里的 `:id` 是一个占位符。
    *   **语法符号**：路径参数使用**冒号 `:`** 开头。`:` 后面的名字就是参数的键（Key）。
    *   **数据映射**：当 URL 变化时（如从 `/users/johnny` 变为 `/users/jolyne`），Vue Router 会自动提取 `johnny` 或 `jolyne` 这个值，并将其存储在 `route.params` 对象中。

*   **【实例教学】**
    **代码块：定义路由**
    ```js
    import User from './User.vue'

    const routes = [
      // 动态字段以冒号开始
      {
        path: '/users/:id',
        component: User
      }
    ]
    ```
    *   **第 1 行**：引入了我们之前写好的用户组件。
    *   **第 5 行**：定义了一个路由规则。注意 `path` 里的 `:id`。这告诉 Vue Router：“任何以 `/users/` 开头，后面跟任意字符的路径，都归这个组件管。”

    **代码块：在模板中使用参数**
    ```vue
    <template>
      <div>
        <!-- 当前路由可以通过 $route 在模板中访问 -->
        User {{ $route.params.id }}
      </div>
    </template>
    ```
    *   **第 4 行**：`$route` 是 Vue Router 注入到组件中的一个特殊对象。`.params.id` 就是我们在路径里定义的那个 `:id` 对应的值。
    *   **预期效果**：
        *   当 URL 是 `http://yoursite.com/users/eduardo` 时，页面上会显示 **User eduardo**。
        *   当 URL 是 `http://yoursite.com/users/johnny` 时，页面上会显示 **User johnny**。

#### **2. 复杂参数：多级路径匹配**

*   **【原文要点】**
    你可以在一个路由路径中设置多个路径参数，它们会自动映射到 `route.params` 对象的对应字段中。

*   **【深度拆解】**
    路径参数可以像俄罗斯套娃一样嵌套。你可以同时捕获“用户名”和“文章ID”。

*   **【实例教学】**
    **代码块：多参数定义**
    ```js
    // 路径定义
    { path: '/users/:username/posts/:postId', component: UserPost }
    ```
    *   **逻辑拆解**：
        *   `:username` 会捕获第二个 URL 片段。
        *   `:postId` 会捕获第四个 URL 片段。
    *   **数据映射表**：

| 匹配模式 | 匹配路径 | route.params 的值 |
| :--- | :--- | :--- |
| `/users/:username` | `/users/eduardo` | `{ username: 'eduardo' }` |
| `/users/:username/posts/:postId` | `/users/eduardo/posts/123` | `{ username: 'eduardo', postId: '123' }` |

    *   **注意**：`route.params` 里的键名（key）完全取决于你在路径中写的参数名（`:xxx`）。

#### **3. 其他路由信息**

*   **【原文要点】**
    除了 `route.params`，`route` 对象还包含 `query`（查询参数）和 `hash`（锚点）等信息。

*   **【深度拆解】**
    *   **`route.query`**：对应 URL 中 `?` 后面的内容。例如 `?page=2` 会变成 `{ page: '2' }`。
    *   **`route.hash`**：对应 URL 中 `#` 后面的内容，常用于页面内锚点跳转。

### 📚 第二章：响应路由参数的变化

#### **1. 核心机制：组件复用**

*   **【原文要点】**
    当用户从 `/users/johnny` 导航到 `/users/jolyne` 时，Vue Router 为了效率，不会销毁旧的组件实例再创建一个新的，而是直接**复用**同一个组件实例。

*   **【深度拆解】**
    *   **为什么这么做？** 销毁和重建组件涉及内存分配和 DOM 操作，比较消耗性能。既然都是 `User` 组件，直接更新数据更高效。
    *   **副作用**：因为组件没有重新创建，所以组件的生命周期钩子（如 `created` 或 `mounted`）**不会被再次调用**。这意味着如果你在 `mounted` 里根据 `id` 去请求用户数据，切换用户时数据不会自动更新。

#### **2. 解决方案 A：监听 $route (Composition API)**

*   **【实例教学】**
    **代码块：使用 watch 监听**
    ```vue
    <script setup>
    import { watch } from 'vue'
    import { useRoute } from 'vue-router'

    const route = useRoute()

    watch(
      () => route.params.id,
      (newId, oldId) => {
        // 对路由变化做出响应...
      }
    )
    </script>
    ```
    *   **第 2 行**：从 Vue 核心库导入 `watch` 函数，用于监听数据变化。
    *   **第 3 行**：从 Vue Router 导入 `useRoute` 钩子。
    *   **第 5 行**：获取当前的路由对象。
    *   **第 7-11 行**：`watch` 的第一个参数是一个函数，它返回我们要监听的值（这里是 `route.params.id`）。第二个参数是回调函数，当 `id` 变化时执行。
    *   **执行逻辑**：页面加载时监听一次，当 URL 的 `id` 从 `johnny` 变成 `jolyne` 时，回调函数被触发，你可以在这里重新请求数据。

#### **3. 解决方案 B：导航守卫 (Navigation Guard)**

*   **【实例教学】**
    **代码块：使用 onBeforeRouteUpdate**
    ```vue
    <script setup>
    import { onBeforeRouteUpdate } from 'vue-router'

    onBeforeRouteUpdate(async (to, from) => {
      // 对路由变化做出响应...
      userData.value = await fetchUser(to.params.id)
    })
    </script>
    ```
    *   **第 2 行**：导入 `onBeforeRouteUpdate` 钩子。这是 Vue Router 提供的专门用于监听路由更新的钩子。
    *   **第 4 行**：回调函数接收两个参数：`to`（即将进入的路由）和 `from`（即将离开的路由）。
    *   **优势**：相比于 `watch`，导航守卫允许你在数据获取完成前“阻拦”导航（例如显示加载状态），甚至可以取消导航。

### 📚 第三章：捕获所有路由或 404 Not found 路由

#### **1. 核心概念：通配符与正则**

*   **【原文要点】**
    常规参数只能匹配由 `/` 分隔的片段。如果你想匹配任意路径（比如处理 404 页面），需要使用自定义的正则表达式。

*   **【深度拆解】**
    Vue Router 支持在路径参数后使用括号 `()` 来定义正则表达式。`(.*)` 表示“匹配任意字符”。

#### **2. 实例：404 页面配置**

*   **【实例教学】**
    **代码块：定义 404 路由**
    ```js
    const routes = [
      // 将匹配所有内容并将其放在 `route.params.pathMatch` 下
      {
        path: '/:pathMatch(.*)*',
        name: 'NotFound',
        component: NotFound
      },
      // 将匹配以 `/user-` 开头的所有内容
      {
        path: '/user-:afterUser(.*)',
        component: UserGeneric
      }
    ]
    ```
    *   **第 5 行**：`/:pathMatch(.*)*` 是一个高级正则。
        *   `:pathMatch`：定义了一个参数名。
        *   `(.*)`：正则表达式，表示匹配任意字符（除换行符外）零次或多次。
        *   `*`：后面的星号表示这个参数是可选且可重复的（即可以匹配 `/`、`/a`、`/a/b` 等）。
    *   **第 11 行**：这是一个更具体的例子。它匹配所有以 `/user-` 开头的路径，后面的内容会被捕获到 `route.params.afterUser` 中。

    **代码块：编程式导航处理 404**
    ```js
    router.push({
      name: 'NotFound',
      // 保留当前路径并删除第一个字符，以避免目标 URL 以 `//` 开头。
      params: { pathMatch: this.$route.path.substring(1).split('/') },
      // 保留现有的查询和 hash 值，如果有的话
      query: route.query,
      hash: route.hash
    })
    ```
    *   **第 4 行**：`substring(1)` 切掉路径开头的 `/`（例如把 `/abc` 变成 `abc`），防止变成 `//abc`。
    *   **第 4 行**：`split('/')` 将字符串按 `/` 分割成数组。
    *   **目的**：当用户访问一个不存在的页面时，我们把错误的路径完整地保存下来，传给 `NotFound` 组件，以便在页面上显示“您访问的页面 [xxx] 不存在”。

### 📚 第四章：高级匹配模式

#### **1. 背景知识**

*   **【原文要点】**
    Vue Router 的路径匹配语法灵感来源于 Express 框架，支持可选参数、零或多个匹配、自定义正则等高级模式。

*   **【深度拆解】**
    虽然文档没有列出所有语法，但核心思想是：Vue Router 不仅仅是简单的字符串匹配，它是一个强大的路径解析器。你可以利用正则表达式来实现非常精细的控制，比如让一个参数在 URL 中出现多次，或者让某个参数是可有可无的。

#### **2. 服务器配置提醒**

*   **【易错提醒/注意】**
    如果你正在使用**历史模式 (History Mode)**（即去掉了 URL 中的 `#`），请务必按照说明正确配置你的服务器。
    *   **原因**：在历史模式下，所有的前端路由（如 `/users/123`）实际上在服务器上并不存在物理文件。如果用户直接刷新页面，请求会发送到服务器。如果服务器没有配置“将所有未知请求重定向到 `index.html`”，服务器会返回 404 错误，而不是让 Vue Router 来处理这个路由。
