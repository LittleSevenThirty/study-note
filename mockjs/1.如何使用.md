# 使用 Mock.js 拦截 Axios 请求实现前端独立开发的技术笔记

---

## 一、概述

在前后端分离的开发模式中，前端往往需要依赖后端提供的 API 接口进行联调。然而，在后端接口尚未就绪或开发进度不同步的情况下，前端可以通过 **Mock 技术**模拟后端响应，从而独立完成页面逻辑、交互和 UI 的开发与测试。

本笔记以 **Vite + Vue 3 + Axios** 项目为基础，介绍如何使用 **Mock.js** 配合 **拦截 Axios 请求**的方式，快速搭建本地 Mock 环境，实现无后端依赖的前端开发流程。

> ⚠️ 注意：本文采用 **运行时拦截（Runtime Interception）** 方案，即在浏览器中通过重写 Axios 的请求逻辑返回模拟数据，而非启动独立 Mock 服务（如 Mock Server）。该方案简单、轻量，适合中小型项目快速上手。

---

## 二、关键词

- **Mock.js**：一个用于生成随机数据的 JavaScript 库，支持模拟各种格式的 JSON 数据。
- **Axios**：流行的基于 Promise 的 HTTP 客户端，用于发送请求。
- **请求拦截（Interception）**：在 Axios 发起真实网络请求前，拦截并返回模拟响应。
- **Vite**：现代化前端构建工具，支持快速开发和热更新。
- **运行时 Mock**：在浏览器环境中直接模拟接口响应，无需额外服务。

---

## 三、准备工作

### 1. 确认项目环境
你的项目已具备以下条件：
- 使用 **Vite** 构建
- 基于 **Vue 3（Composition API）**
- 使用 **Axios** 作为 HTTP 客户端
- 已安装 `axios`（当前版本 `^1.5.1`）

### 2. 安装 Mock.js
在项目根目录执行：

```bash
npm install mockjs --save-dev
```

> 虽然 Mock.js 通常用于 Node.js 环境，但它也可以在浏览器中运行，因此可安全用于前端项目。

## 四、正式内容

### 步骤 1：创建 Mock 目录结构

建议将 Mock 相关代码集中管理，例如：

```
src/
├── mock/
│   ├── index.ts          # Mock 入口文件
│   ├── user.ts           # 用户相关接口
│   ├── article.ts        # 文章相关接口
│   └── utils.ts          # 工具函数（可选）
└── main.ts               # 项目入口
```

### 步骤 2：编写 Mock 规则（以用户列表为例）

**`src/mock/user.ts`**

```ts
import Mock from 'mockjs'

// 模拟 GET /api/users
Mock.mock('/api/users', 'get', {
  code: 200,
  message: 'success',
  data: {
    'list|5-10': [{               // 随机生成 5~10 条用户
      'id|+1': 1,                 // 自增 ID
      name: '@cname',             // 中文姓名
      email: '@email',
      avatar: '@image(80x80, @color, @name)',
      createdAt: '@datetime'
    }]
  }
})

// 模拟 POST /api/login
Mock.mock('/api/login', 'post', (options) => {
  const { body } = options
  const params = JSON.parse(body)
  
  if (params.username === 'admin' && params.password === '123456') {
    return {
      code: 200,
      message: '登录成功',
      data: {
        token: Mock.Random.string(32),
        user: {
          id: 1,
          username: 'admin',
          nickname: '管理员'
        }
      }
    }
  } else {
    return {
      code: 401,
      message: '用户名或密码错误',
      data: null
    }
  }
})
```

> ✅ Mock.js 支持丰富的占位符（如 `@cname`, `@email`, `@image`），详见 [Mock.js 官方文档](http://mockjs.com/)

### 步骤 3：启用 Mock（仅在开发环境）

**`src/mock/index.ts`**

```ts
// 仅在开发环境启用 Mock
if (import.meta.env.DEV) {
  // 引入所有 mock 模块
  import('./user')
  import('./article')
  // 可继续引入其他模块...

  console.log('%c Mock 启动成功！', 'color: green; font-weight: bold;')
}
```

> 💡 利用 `import.meta.env.DEV` 确保 Mock 代码**不会被打包到生产环境**。

### 步骤 4：在项目入口引入 Mock

**`src/main.ts`**

```ts
import { createApp } from 'vue'
import App from './App.vue'
import router from './router'
import { createPinia } from 'pinia'

// 👇 在最顶部引入 Mock（必须早于 Axios 使用）
import './mock'

const app = createApp(App)
app.use(createPinia())
app.use(router)
app.mount('#app')
```

> ⚠️ 顺序很重要！必须在创建 Vue 实例**之前**加载 Mock，否则 Axios 请求可能先于 Mock 规则注册而失效。

### 步骤 5：验证 Mock 是否生效

在组件中使用 Axios 调用接口：

```ts
// 示例：调用用户列表
import axios from 'axios'

const fetchUsers = async () => {
  const res = await axios.get('/api/users')
  console.log(res.data)
}
```

打开浏览器控制台，应看到模拟的用户数据，并且 **Network 面板中无真实请求发出**（因为被 Mock.js 拦截了）。

> 🔍 注意：Mock.js 是通过覆盖 `XMLHttpRequest` 和 `fetch` 实现拦截的，因此对 Axios（基于 XHR/fetch）完全兼容。

## 五、补充说明（常见问题）

### Q1：为什么不用 `vite-plugin-mock`？
- `vite-plugin-mock` 是基于 **Mock Server** 的方案，需启动中间层代理，配置较复杂。
- 本方案更轻量，适合快速验证，且不依赖 Vite 插件生态。

### Q2：如何关闭 Mock？
只需注释掉 `src/main.ts` 中的 `import './mock'` 即可，或通过环境变量控制：

```ts
// src/mock/index.ts
if (import.meta.env.DEV && import.meta.env.VITE_USE_MOCK !== 'false') {
  // ...
}
```

然后在 `.env` 中设置：
```
VITE_USE_MOCK=false
```

### Q3：Mock 数据能否动态变化？
可以！Mock.js 支持函数形式返回值，例如：

```ts
Mock.mock('/api/random', 'get', () => ({
  time: new Date().toISOString(),
  value: Math.random()
}))
```

每次请求都会返回新数据。

## 六、总结

通过以上步骤，你已成功在 Vite + Vue 3 项目中集成 Mock.js，实现了：
- 开发阶段无后端依赖
- 自动拦截 Axios 请求
- 返回结构化模拟数据
- 生产环境自动剥离 Mock 代码

此方案简单高效，非常适合个人项目或团队初期快速迭代。随着项目规模扩大，可考虑迁移到更强大的 Mock 服务（如 MSW、JSON Server 等），但对大多数场景，Mock.js + 运行时拦截已足够。

> 📌 建议：将 Mock 规则与真实接口文档保持一致，便于后续无缝切换至真实后端。
